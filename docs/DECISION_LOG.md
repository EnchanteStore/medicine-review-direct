# Decision log

Format: ID, date, decision, rationale, alternatives rejected, status.

## Technical decisions made in Phase 1

| ID    | Decision                                                                                                                             | Rationale                                                                                         | Alternatives rejected                                                                          |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| D-001 | pnpm + Turborepo monorepo with one Next.js app and four small packages                                                               | Shares domain and validation logic with the future Expo app without a separate service            | Single-package app (harder to share with mobile); separate staff app now (cost before benefit) |
| D-002 | Next.js 16 App Router, React 19, server actions for forms                                                                            | Server-side validation and auth by default, progressive enhancement, one deployable               | Separate API server (more moving parts)                                                        |
| D-003 | Staff routes under `/staff` in the same app, gated server-side and by RLS                                                            | Simplest; split later if it earns the cost                                                        | Separate staff app now                                                                         |
| D-004 | Supabase (Postgres 17, Auth, Storage) with RLS as final authority; web app uses user JWTs, not the service role                      | Least privilege; a bug in app code cannot bypass row isolation                                    | App-level authorisation only                                                                   |
| D-005 | `auto_expose_new_tables = false` and explicit column-level grants                                                                    | New tables are private until deliberately exposed                                                 | Supabase default auto-grants                                                                   |
| D-006 | Role helpers as `security definer` functions in a private `app` schema with pinned `search_path`                                     | Avoids RLS recursion and search_path hijacking; not callable as RPC except where granted          | JWT custom claims for roles (stale until token refresh; suspension would lag)                  |
| D-007 | Ops admin excluded from all clinical predicates; verified pharmacists get assignment-scoped access only (Phase 4)                    | Brief: ops must not automatically see clinical content; least privilege for clinicians            | Blanket clinician read access                                                                  |
| D-008 | Audit log and consents append-only via triggers that also block the table owner                                                      | Tamper evidence; withdrawal recorded as a new row                                                 | Soft-delete flags                                                                              |
| D-009 | `on delete restrict` from data tables to `auth.users`                                                                                | Account deletion must respect clinical retention; prevents accidental cascades                    | `on delete cascade`                                                                            |
| D-010 | Prices in a `products` table (pence), read server-side, no hard-coded fallback                                                       | Server-controlled, admin-configurable, audited changes                                            | Environment variables or constants                                                             |
| D-011 | Email links use token-hash templates verified at `/auth/confirm`                                                                     | Works across devices and in SSR; no health data in email                                          | Default PKCE redirect (breaks when opened on another device)                                   |
| D-012 | Mailpit (bundled by Supabase CLI v3, replacing Inbucket) for local email capture                                                     | Same role as Inbucket; built in                                                                   | Real email provider in dev                                                                     |
| D-013 | Password policy 12+ chars with a letter and a digit, max 72 bytes                                                                    | Length over complexity (NCSC guidance); bcrypt limit                                              | Complex composition rules                                                                      |
| D-014 | In-memory rate limiter behind a `RateLimiter` interface; strict per-email, looser per-IP                                             | Works now; swap to Postgres/Redis store before production without changing callers                | No app-level limiting                                                                          |
| D-015 | Sign-up, reset and resend give identical responses whether or not the account exists, including when Auth throttles a repeat sign-up | Prevents account enumeration                                                                      | Distinct "already registered" message                                                          |
| D-016 | Date of birth as separate day/month/year inputs                                                                                      | GOV.UK pattern; easier for older users than date pickers                                          | `<input type="date">`                                                                          |
| D-017 | 18px base font, 48px targets, system fonts                                                                                           | Accessibility for older users; no web-font download                                               | Default 16px                                                                                   |
| D-018 | Pinned TypeScript 5.9 and ESLint 9                                                                                                   | typescript-eslint and eslint-config-next do not yet support TypeScript 7 / are proven on ESLint 9 | Latest majors                                                                                  |
| D-019 | Background jobs via Postgres-backed queue (pg-boss or pgmq) in a later `apps/worker`                                                 | One stateful dependency; idempotency in SQL                                                       | Redis/BullMQ, external queue service                                                           |
| D-020 | Packages consumed as TypeScript source (`transpilePackages`)                                                                         | No package build step; fast feedback                                                              | Building each package to `dist`                                                                |
| D-021 | Non-staff visiting `/staff` get a 404                                                                                                | Does not advertise the staff area                                                                 | 403 page                                                                                       |
| D-022 | Pre-launch: `noindex`, robots disallow, and a "not yet accepting patients" notice                                                    | Honest about status; avoids indexing draft content                                                | Indexable site                                                                                 |
| D-023 | Phone number optional in Phase 1 profile; stored as E.164 UK only                                                                    | Needed for consultations later; verification arrives in Phase 2                                   | Required now                                                                                   |

## Environment notes

- The Cloud VM needed Docker installed and a `DOCKER-USER` iptables ACCEPT rule because stale
  legacy iptables rules dropped container-to-container traffic. This is a VM quirk, not a project
  requirement; CI runners do not need it.
